# Architecture: games layer

Static site, no bundler, no runtime network calls. Python renders HTML; the browser runs native ES modules. See [GAMES-PLAN.md](GAMES-PLAN.md) for goals and decisions; this file says where code lives.

## Data flow

```
content/*.json (lessons)          content/games/<game>.json (items, schema: content/games/SCHEMA.md)
        \                                   /
         scripts/games_data.py  (stdlib validator + loader; used by build.py, check.py, tests/)
                         |
                scripts/build.py  ->  site/lessons/<lesson>.html   (<section id="games"> mount + module script)
                                      site/games/index.html        (hub)
                                      site/games/data/<game>.json  (reviewed items only)
                         |
   browser: site/games/<game>/main.js  imports  site/games/ui/*  and  site/games/engine/*
```

A game appears on the public site only when its file is valid, its name does not start with `_`, and it has at least one item with `needs_review: false`. Until the first such game exists, the build emits no games section and no "Games" nav link, so existing pages stay byte-identical.

## Module boundaries

| Path | Holds | May import | Must not |
|---|---|---|---|
| `site/games/engine/*.js` | Pure logic: tier adaptation, scoring, scheduling, progress reducers, item selection. | other `engine/*` | touch `document`, `window`, `localStorage`, `Date.now`, `Math.random` (pass them in) |
| `site/games/ui/*.js` | Shared Preact components (choice list, hint ladder, feedback live region, Peppy SVG, progress store adapter). | `engine/*`, `site/vendor/*` | contain game-specific content or rules |
| `site/games/<game>/*.js` | One game: `main.js` mounts into `#game-<game>`, plus game-specific components and CSS. | `ui/*`, `engine/*`, `site/vendor/*` | import another game's folder |
| `site/vendor/*` | Vendored third-party ESM. Never edited. | each other | |
| `site/games/data/*.json` | Generated by `build.py`. Never hand-edited. | | |
| `tests/*.py` | Python unittest for the validator and build gating. | | |
| `site/games/engine/__tests__/*.test.js` | `node --test` tests for engine and vendor integrity. | | |

Modules use relative imports with the `.js` / `.mjs` extension (browsers and node resolve them identically). No import maps, no bare specifiers.

## Where new X belongs

- **A new game**: `content/games/<slug>.json` + `site/games/<slug>/main.js` (+ `<slug>.css`). Add the stylesheet via the game's `main.js` (`<link>` injection) or a build step in a follow-up card; do not edit another game.
- **A new rule shared by 2+ games** (scoring, scheduling, mastery): `engine/`, with a `__tests__` file in the same change.
- **A new shared widget**: `ui/`. If only one game uses it, keep it in that game's folder until a second game needs it.
- **A new item field**: `content/games/SCHEMA.md` and `scripts/games_data.py` in the same change, plus a failing-fixture test in `tests/test_games_data.py`. SCHEMA.md and the validator must stay in lockstep.
- **A new check on built output**: `scripts/check.py`. Keep it deterministic and offline.
- **Lesson-page markup for games**: `render_games_section` in `scripts/build.py`. Pages must remain byte-stable when nothing changed.
- **Persistent learner state**: `localStorage` only, behind one `ui/` store adapter (engine stays pure). No network, no analytics.

## Ceilings and budgets

- **Files**: hand-written JS/CSS under `site/games/` (excluding `data/` and `vendor/`) stays at or under **400 lines** per file; `check.py` enforces it. Split by responsibility before reaching it.
- **Per game**: JS + CSS under 40 KB uncompressed, excluding vendored Preact/htm.
- **Accessibility baseline** every component must meet: keyboard-complete, `aria-live` feedback, no color-only meaning, `prefers-reduced-motion` respected, no timers.
- **Content safety**: no dosing, efficacy numbers, brand/product comparisons or treatment guidance. `games_data.py` lints for dose-like quantities and a drug/brand list; a hit fails the build and needs a human rewrite.

## Tests and CI

```sh
python scripts/build.py && python scripts/check.py && git diff --exit-code -- site/
python -m unittest discover -s tests   # validator + gating
node --test "site/games/**/__tests__/*.test.js"   # engine + vendor hash tests (Node 22+, no package.json)
```

CI (`.github/workflows/site.yml`) runs all of the above with `actions/setup-node` (Node 22).

## Vendored dependencies

No npm at build or runtime; files were taken from the official npm tarballs and are not edited, except: `//# sourceMappingURL` comment removed (no `.map` is shipped) and, in `hooks.mjs`, the bare import `"preact"` rewritten to `"./preact.mjs"` so browsers resolve it without an import map. Both changes are one-line and reproducible from the tarball.
